# 交互规范（手势与键位）

这份表是**交互的单一来源**。视觉有 `src/plugins/sph-tui/theme/theme.ts` 一处画笔；
交互此前没有对应物，于是每个新表面都在自由发挥。这一份补上那个位置。

规则只有一条：**新增/改动任何表面之前，先来这里挑手势**。表里没有的组合，要么
改用手势表里已有的读法，要么**先改这份表**（连同理由）再动代码。

它是**描述性**的——记录的是已经在用的习惯，不是理想设计。现状里刻意的差异
（见「刻意保留的差异」）不会被抹平，只会被写明。

---

## 一、三条判据

挑手势前先回答三个问题：

1. **谁在用？** 鼠标 / 键盘 / 都要。
   - 只要鼠标 → 必须再给一条键盘路径，否则键盘用户够不着（工具行的逐行展开就是这种例外，
     它用 `Ctrl+O` 整批开合兜底）。
   - 只要键盘 → 同样要补鼠标路径（菜单的确认以前只有 Enter，现在双击也可以）。
2. **有破坏性吗？** 执行命令、删除、覆盖 → 必须比「打开」多一层代价（双击 / 显式确认项）。
   双击在列表里读作激活，所以**破坏性动作不要挂在双击上**，挂在 Enter 上（Enter 有「多按一次 ↓」的初始焦点保护）。
3. **在哪一层？** `src/tui/` 是通用控件，`src/plugins/sph-tui/` 是内容表面。
   同一个动作在不同层可能导出不同手势，**但每一层内部必须一致**。

## 二、手势语义总表

行是手势，列是表面族。`—` 表示「该族没有这个手势」。

| 手势 | 选择列表<br>`SelectList` | 折叠行<br>工具行 / 工具组 / 报告分组 | 视口<br>转录 / 弹窗正文 / 报告正文 | 编辑器<br>输入框 |
|---|---|---|---|---|
| **悬停** | 预览底色（不动高亮） | 预览标题底色 | — | — |
| **单击** | 移高亮 | **选中该行**（选中底） | 落光标 / 起拖选 | 移光标 |
| **双击** | **激活**（＝Enter） | **开合** | 选词 | 选词 |
| **三击** | — | 选行 | 选行 | 选行 |
| **Enter** | **激活** | 激活当前行 | — | 提交 |
| **滚轮** | **移高亮** | — | **滚视口** | 滚视口 |
| **PageUp/Down · Home/End** | 列表内翻页 / 首尾 | — | 视口翻页 / 首尾 | 视口翻页 / 首尾 |
| **打字** | 过滤（可过滤的菜单、命令面板）/ `/` 搜索（报告） | — | — | 输入 |
| **右键** | — | — | **复制选区**（无选区则不拦截，交回终端） | — |
| **Esc** | 关（取消） | — | 中断轮次 | 中断轮次 |
| **Tab** | — | — | 切报告 tab | 补全 |

**选择列表族的成员**（同一套手势，四处）：编辑器斜杠菜单 / 补全菜单、弹窗选择器
（`dialogs.ts` 的 `SelectBody`）、报告弹窗的条目列表、命令面板。

**折叠行族的成员**（同一套手势，三处）：转录里的工具行与工具组、报告弹窗的分组。
共用 `DoubleClickTracker`，并共用开合字形 `›`（收起）/ `✦`（展开）。

## 三、两个手势为什么是这样

**双击 = 开合/激活，单击只移高亮。** 单击在文本表面必须留给「选中」和「拖选」，
不能同时承担激活——所以激活上移到双击。列表里同样如此：单击是「看着它」，
双击才是「打开它」。这条在全项目一致，**不要再造第三种开合手势**。

**滚轮在列表里移高亮、在视口里滚视口。** 列表短（菜单通常 ≤ 10 项、选择器 ≤ 一屏），
滚视口看不全，移高亮一步到位；视口长（转录、报告正文），必须滚。判定依据是**内容的长度**，
不是控件的种类：将来若有短视口，按「内容装得下就移高亮」处理。

## 四、键位

两级：`tui.*`（框架层，`src/tui/input/keybindings.ts`）与 `app.*`（应用语义，
`src/plugins/sph-tui/input/app-keybindings.ts`）。**两张表不混**——框架不认识「中断」这种产品概念。

### 应用级 `app.*`

| 动作 | 默认键 | 说明 | 生效条件 |
|---|---|---|---|
| `app.interrupt` | `Escape` | 取消 / 中断当前轮次（并恢复排队消息） | 轮次进行中 |
| `app.exit` | `Ctrl+D` | 退出 | 输入框为空 |
| `app.clear` | `Ctrl+C` | 中断轮次 / 清空输入 / 再按一次退出 | 任意 |
| `app.tools.expand` | `Ctrl+O` | **整批**展开或收起工具输出 | 任意 |
| `app.command` | `Ctrl+P` | 命令面板 | 任意 |
| `app.help` | `F1` | 帮助 | 任意 |
| `app.followUp` | `Alt+Enter` | 排队一条 follow-up（本轮结束后跑） | 任意 |
| `app.approval.cycle` | `Shift+Tab` | 循环审批模式（ask / auto / yolo） | 任意 |
| `app.agent.cycle` | `Ctrl+Tab` | 循环会话 agent | 轮次空闲 |
| `app.copy` | `Ctrl+Shift+C` / `Alt+C` | 复制当前选区 | **有选区时**才消耗按键 |

`app.copy` 给两个键是因为 `Ctrl+Shift+C` 在部分终端（Windows Terminal、iTerm2）被
终端自己截走做「复制终端选区」——应用收不到。`Alt+C` 是那条通路被占时的备用键。
**有选区才消耗按键**：没有选区时把 `Ctrl+Shift+C` 放行给终端，终端自身的复制语义留得下来。
除键位外还有一条等效通路：`/copy` 命令（键盘可发现、任何终端都能用）。

### 框架级 `tui.*`（摘录，完整见 `keybindings.ts`）

| 动作 | 默认键 |
|---|---|
| `tui.input.submit` | `Enter` |
| `tui.input.newLine` | `Shift+Enter` / `Ctrl+J` |
| `tui.input.tab` | `Tab`（补全；空格后按 Tab 强制触发） |
| `tui.input.interrupt` | `Ctrl+C` |
| `tui.select.up` / `.down` | `↑` / `↓` |
| `tui.select.confirm` | `Enter` |
| `tui.select.cancel` | `Esc` / `Ctrl+C` |
| `tui.altScreen.pageUp` / `.pageDown` | `PageUp` / `PageDown` |
| `tui.altScreen.previousPrompt` / `.nextPrompt` | `Ctrl+Shift+↑` (或 `Ctrl+↑`) / `Ctrl+Shift+↓` (或 `Ctrl+↓`) |
| `tui.altScreen.top` / `.bottom` | `Home` / `End` |

### 输入框的触发符号

| 符号 | 作用 |
|---|---|
| `/` | 行首：斜杠命令菜单；命令后加空格：该命令的参数补全 |
| `@` | 路径 / 附件补全（支持 `@"带空格的路径"`） |
| 无符号 | 裸路径也补全：含 `/`、以 `.` 或 `~/` 开头；空格后按 `Tab` 强制触发 |

## 五、刻意保留的差异

这些**不是漏改**，改之前先读理由：

| 差异 | 理由 |
|---|---|
| 滚轮在列表里移高亮、在视口里滚视口 | 见上：按内容长度分，不按控件种类 |
| 浮层底色两档：短时弹窗铺 `dialogBg`，长驻报告面板贴 `bg` | 短时弹窗是「浮起来的一层」，长驻面板是「看一整页」。两处注释互相指路 |
| `cancel` / `deny` / `skip` 三个放弃动词并存，其余统一 `close` | 它们是真语义区分：有未提交输入 / 审批拒绝 / 跳过这一步。`dismiss` 已并入 `close` |
| 弹窗宽度按 `DIALOG_LAYOUTS` 分档（confirm / select / input / document / loading） | 不同的内容配不同的宽高，不是风格漂移 |
| 紧凑档的底边提示只剩键位（`↑↓ · Enter · Esc`） | 列预算是按字符算的，加动词可能把 `Esc` 挤掉 |
| 工具行只认鼠标（双击）开合 | 文本行不能占用单击，见上。键盘路径由 `Ctrl+O` 整批承担 |
| 报告弹窗不报位置读数（`12/31`） | 这里滚轮滚的是视口，那个数跟眼前看到的位置对不上，反而误导（见 `report/dialog.ts`） |
| 列表/菜单报位置读数（`3/15`），放在底边框右槽 | 那里滚轮移的是高亮，读数与眼前位置一致。加载弹窗的秒表也用这同一槽 |

## 六、新增表面时的检查清单

1. 先在上面**手势语义总表**里挑一列照抄，不要发明新读法。
2. 每个「只有鼠标」的手势都问一遍：键盘怎么做到？反之亦然。
3. 破坏性动作不挂双击；挂在 Enter 上，并利用 `setInitialIndex` 的初始焦点避让。
4. 加了 `app.*` 键位 → 同步 `APP_KEYBINDINGS`（`/help` 的键位表从它取数）。
5. 加了命令 → 同步 `src/plugins/sph-tui/commands/index.ts` 的注册表（`/help` 与命令面板都从它取数）。
6. 若确实需要新读法，**先改这份表**（连同选它的理由），再改代码。
